# trafmix

Контроллер (малинка/Ubuntu) гоняет **разнотипный трафик с лимитом скорости** (UDP-файл,
TCP, HTTP-загрузка, микс) на твои тестовые сервера и отдельно мерит, **живы ли они**.
Один сервер с «шумом», другой контрольный — сравниваешь на таймлайне.

Только для своих серверов. Это нагрузочно-измерительный стенд.

## Поднять панель

```bash
./trafmix up            # → http://<ip>:8744
```
Нужен `python3` (есть везде). `iperf3`/`curl` поставятся сами, если их нет.
Как сервис: `sudo ./trafmix service`. Остановить локально: `./trafmix stop`.

Панель без своей авторизации — вешай на localhost или за свой VPN/прокси.

## Поставить ноду (на каждый сервер)

```bash
git clone <repo> trafmix && cd trafmix
sudo ./trafmix node          # [iperf_port=5201] [http_port=8745]
```
Ставит `iperf3 -s` и крошечный http-источник файла как сервисы (под `Nice`/`CPUWeight`,
чтобы не мешать VPN). Открой порты только для IP малинки. Потом в панели:
**+ сервер** → адрес, порт `5201`, URL `http://<ip>:8745/file`.

## Как это работает

- **Трафик** — задания по расписанию: UDP-файл (`iperf3 -u --reverse`), TCP, HTTP-загрузка
  (`curl --limit-rate`) или **микс** (случайный тип/параметры каждый раз). У каждого свой
  лимит скорости. Сверху **общий лимит** — одновременно идёт один поток, суммарно не больше
  лимита (бережёт домашний аплинк и сервера). «Пауза» глушит весь трафик.
- **Измерение** — лёгкая проверка «жив ли сервер» (TCP/TLS, без нагрузки) с таймлайном и %
  доступности. Контрольный сервер получает только её. Проверяй порт сервиса (443/порт VPN),
  не iperf.

## Что где

```
trafmix            один скрипт: up / node / service / stop
controller/        панель: trafmix.py (API+планировщик) · runners.py · db.py · static/
agent/httpfile.py  http-источник файла для ноды
controller/trafmix.db   данные (sqlite, хранит неделю прогонов и проверок)
```

Стек: Python 3.9+ стандартная библиотека (без pip) + `iperf3` + `curl`.
